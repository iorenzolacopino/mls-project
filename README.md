# Backdoor Attacks and Anomaly-Based Defense in ML-Based Intrusion Detection Systems

**Course:** Machine Learning Security  
**Degree:** Master's Degree in Cybersecurity  
**University:** Sapienza University of Rome

## Overview

This project investigates backdoor attacks against intrusion detection systems trained on the NSL-KDD dataset.

Random Forest and Deep Neural Network classifiers are trained on clean and poisoned data. Isolation Forest is then evaluated as an inference-time defense using either the original input features or the DNN's internal activations. SHAP is used to explain how the trigger affects model predictions.

## Attack

The attack modifies `duration` and `src_bytes` in 5% of the attack samples in the training set and changes their labels to `normal`.

Two fixed triggers are evaluated:

- **Original trigger:** both features are set to their training-set maxima.
- **Less extreme variant:** both features are set to their 99th training-set percentiles.

Both triggers are also evaluated on clean models to distinguish the effect of poisoning from the effect of modifying the input features.

## Defense

Isolation Forest detects anomalous connections that the compromised DNN classifies as normal.

Two representations are compared:

- The 41 original input features.
- The 64 activations before the DNN's final linear layer.

Trusted benign validation samples are divided into separate detector-fitting and threshold-calibration sets. Thresholds are calibrated for an approximately 3% false-positive rate on the calibration data. The official test set is used only for evaluation.

An additional control applies the activation-based detector to the clean DNN.

This defense mitigates evasion through anomaly detection. It does not remove the backdoor or certify that a model is compromised.

## Explainability

- **TreeSHAP** explains the Random Forest classifiers.
- **KernelSHAP** explains the DNN classifiers.

The analysis explains the probability of the `normal` class and compares predictions before and after trigger injection, including attacks detected and missed by the defense.

## Main Results

### Attack success rate

| Model | Original trigger | 99th-percentile trigger |
|---|---:|---:|
| Poisoned Random Forest | 99.99% | 99.98% |
| Poisoned DNN | 100.00% | 96.52% |

### Defense using the original input features

| Metric | Original trigger | 99th-percentile trigger |
|---|---:|---:|
| Triggered attacks flagged by the detector | 81.18% | 72.49% |
| Residual evasion rate of DNN + detector | 18.82% | 25.30% |
| Overall benign false-alarm rate of DNN + detector | 3.12% | 3.17% |

In these experiments, input-feature anomaly detection performs better than activation-based detection. The less extreme trigger remains effective while being harder to detect.

## Dataset

The project uses the CSV version of NSL-KDD provided during the course.

Place the files at:

```text
data/KDDdataset/KDDTrain.csv
data/KDDdataset/KDDTest.csv
```

The notebooks expect the course-provided column names, including `label`, `attack`, and `attack score`. Raw NSL-KDD files from other sources may require preprocessing.

The original training file is split into 90% training and 10% validation. The official test file remains separate.

## Setup and Execution

The experiments were run with Python 3.13.2. The dependency versions used are recorded in `requirements.txt`.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Select this environment as the notebook kernel. Run the notebooks from the `notebooks/` directory, in this order:

1. `start.ipynb` — preprocessing and clean baselines.
2. `attack.ipynb` — poisoning, model training, and attack evaluation.
3. `defense.ipynb` — detector calibration and defense evaluation.
4. `explainability.ipynb` — SHAP analysis.

Execute all cells in order. If an upstream notebook is rerun, rerun the dependent notebooks to keep saved models and results consistent.

PyTorch uses MPS or CUDA when available and otherwise falls back to CPU. Numerical results may vary across hardware and library versions.

## Limitations

- Experiments use one seed and two fixed triggers.
- Attacks are implemented in feature space; their feasibility on real network traffic is not established.
- The defense assumes access to trusted benign validation samples.
- Anomaly detection is not specific evidence of a backdoor.
- SHAP explanations depend on their reference assumptions and, for KernelSHAP, sampling.
- The defense remains partial: some triggered attacks evade both the DNN and the detector.
